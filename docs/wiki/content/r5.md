# Rung 5 · voting

`ladder/rungs/r5.py` — built and measured. **k calls per document.**

## Role

- Sample the extractor k times and take the majority.
- **Majority on the normalised code, never on the string.** `cramping` and `Muscle cramp` are the same answer; a string vote splits them and reports disagreement that does not exist.
- Normalise with the same function rung 1 uses — `registry.normalise_term` — so the two agree by construction.
- **Never withdraws.** [[r2]] owns abstention.

## Settings

`manifest.rungs.5`

| Setting | Value | Note |
|---|---|---|
| `k` | 3 | samples per document |
| `temperature` | 0.7 | **deliberately not 0** — identical samples cannot vote |

- This is the one place the project departs from temperature 0, which is why it lives in the manifest rather than a default argument.
- Temperature is **part of the result**, not a tuning detail. Record it in the run stamp alongside backend and release; a claim about sampling behaviour is meaningless without the value attached.

### Guards, all raising

| condition | why it raises |
|---|---|
| `llm is None` | skipping silently would report *voting did not help*, which is a different claim from *voting did not run* |
| `k < 2` | one sample cannot vote |
| `temperature == 0.0` | pays k times for one answer repeated k times |

## Cost is k × documents — corrected from the spec

The spec said *k calls per record*. The implementation samples each **document**
k times and matches mentions by span, which is cheaper and is what every figure
below reflects: 35 documents × 3 = **105 calls** for 169 records.

Documents that produced no rung 0 mentions cost nothing — the loop is over
documents that have records.

## What to write

- The winning code into `rec.sct`.
- The vote spread into `checks`, e.g. `checks["r5_votes"] = {"55300003": 2, "": 1}`. **The spread is the interesting artefact** — a 2–1 split and a 3–0 split are different states that a single winner hides.
- A tie is a real outcome. Decide and record the rule: leave the record unchanged, or treat a tie as no answer.

### Outcomes

| outcome | meaning |
|---|---|
| `unanimous` | all k samples agree on the code |
| `split` | samples disagree |
| `tie` | no plurality |
| `changed` | consensus differs from the greedy answer |
| `unanimous_none` | all k samples returned no code |
| `not_resampled` | **the mention was not re-found by any sample** |

`unanimous_none` is **evidence written for [[r2]]**, not a withdrawal here. A
rung 5 that nulled the record itself would collapse [[r1]]'s rejection rate
without accuracy moving — the same confound measured at [[r0]] mode B and
[[r3]].

`not_resampled` was not in the spec. It is a **third outcome**, neither
agreement nor disagreement. An implementation without it folds these records
into one or the other and reports consensus over records never re-observed.

## Ledger

One row per record, `rung=5`, carrying the **sum** across all k calls: summed tokens, and `latency_ms` for the whole set. Per-call latency loses meaning once k calls are batched; what the run needs is the record's total.

`api_calls` is k per **document**, not per record — divide accordingly or the
per-record cost is overstated by the mention count.

## Measured — dev split, 40 docs, k=3, temperature 0.7

    records voted on   169   calls 105
    documents sampled  35 x k = 105 calls
       unanimous          3  (2%)
       split              0  (0%)
       tie                0  (0%)
       changed            3  (2%)
       unanimous_none     0  (0%)
       not_resampled    166  (98%)
    vote spread {'3': 3}
    tokens 55704   parse failures 0   505.41s

**98% of mentions were not re-found by any of three samples.** The voting
mechanism had 3 records to vote on. Consensus was computed over 2% of the input.

This is not disagreement and must not be reported as agreement either. At
temperature 0.7 the extractor's span output is unstable enough that almost
nothing from the greedy pass reappears. **An agreement metric requires a set
that persists across samples, and here it does not.**

The 5-document smoke run showed 38% `not_resampled`; at 40 documents it is 98%.
Quote the 40-document figure.

### Document denominator

Rung 5's denominator is **35 documents**, rung 0's is 40. Five documents
produced no mentions, so they have nothing to resample. Legitimate, and stated
here because an unexplained denominator shift is indistinguishable from a
silent skip.

## The cost question this rung exists to ask

- k calls per record against one call for [[r0]]. If the marginal errors prevented do not justify 3× tokens, **the honest finding is to stop at a lower rung** — which is the whole point of the ladder.
- **Measured: 55,704 tokens, 0 errors prevented.** Cheaper than [[r3]]'s 72,539 by tokens and the slowest layer by wall clock at 505s. This is why the three cost measures are kept separate rather than fused.

## How you will know it works

- **On the gold control**, k samples of a correct answer should agree; disagreement there is the extractor being unstable, not voting failing. Gold spans ground by construction, so `not_resampled` should be near zero — a large count indicts the sampler, not the corpus. **Not yet run.**
- Vote spread is worth reporting on its own: if the model is 3–0 on almost everything, voting costs 3× and buys nothing, and that is a publishable null result.
- `not_resampled` must be reported, always, **before** any agreement figure.
- Measure alone with `run ablate` so the k-call cost is attributable to rung 5.

## Resolved

- **"If the model is 3–0 on almost everything, voting costs 3× and buys nothing."**
  Confirmed — `vote spread {'3': 3}`, unanimous on every record it could vote on.
  The stronger finding is underneath it: it could only vote on 2% of the input.

## Open

- **Span matching is exact-offset, not normalised.** The spec requires majority on the normalised code via `registry.normalise_term`; matching mentions between samples by exact span is a separate step and may be inflating `not_resampled`. This must be checked before 98% is published as extractor instability.
- Whether `not_resampled` falls at lower temperature, and whether that is worth the reduced spread, is untested.
- [[r2]] does not yet read `checks["r5_unanimous_none"]`; it fired 0 times, so nothing has exercised the channel.
