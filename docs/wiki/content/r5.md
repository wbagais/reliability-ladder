# Rung 5 · voting {{todo|NOT STARTED}}

`ladder/rungs/r5.py` — not written. **k calls per record.** The most expensive rung.

Specified below so it can be built without re-deriving the contract. See [[contributing]].

## Role

- Sample the extractor k times and take the majority.
- **Majority on the normalised code, never on the string.** `cramping` and `Muscle cramp` are the same answer; a string vote splits them and reports disagreement that does not exist.
- Normalise with the same function rung 1 uses — `registry.normalise_term` — so the two agree by construction.

## Settings

`manifest.rungs.5`

| Setting | Value | Note |
|---|---|---|
| `k` | 3 | samples per record |
| `temperature` | 0.7 | **deliberately not 0** — identical samples cannot vote |

- This is the one place the project departs from temperature 0, which is why it lives in the manifest rather than a default argument.

## What to write

- The winning code into `rec.sct`.
- The vote spread into `checks`, e.g. `checks["r5_votes"] = {"55300003": 2, "": 1}`. **The spread is the interesting artefact** — a 2–1 split and a 3–0 split are different states that a single winner hides.
- A tie is a real outcome. Decide and record the rule: leave the record unchanged, or treat a tie as no answer.

## Ledger

One row per record, `rung=5`, carrying the **sum** across all k calls: `api_calls=k`, summed tokens, and `latency_ms` for the whole set. Per-call latency loses meaning once k calls are batched; what the run needs is the record's total.

## How you will know it works

- **On the gold control**, k samples of a correct answer should agree; disagreement there is the extractor being unstable, not voting failing.
- Vote spread is worth reporting on its own: if the model is 3–0 on almost everything, voting costs 3× and buys nothing, and that is a publishable null result.
- Measure alone with `run ablate` so the k-call cost is attributable to rung 5.

## The cost question this rung exists to ask

- k calls per record against one call for [[r0]]. If the marginal errors prevented do not justify 3× tokens, **the honest finding is to stop at a lower rung** — which is the whole point of the ladder.
