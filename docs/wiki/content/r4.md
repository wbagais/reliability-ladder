# Rung 4 · LLM-as-judge

`ladder/rungs/r4.py` — built and measured. **+1 call per record.**

## Role

- A second model scores the record.
- **Must be a different model family from the extractor.** A model judging its own output measures self-consistency, not correctness. Record both in `manifest.model` — `extractor` and `judge`. Enforced: `r4.apply` raises if the two model strings match.

## Why it runs after voting

- Order is `[0, 1, 2, 3, 4, 5, 6]`. The judge sees what [[r5]] corrected and what [[r2]] voted on, so it grades the best available answer rather than a draft.
- [[r1]] runs in `observe` mode precisely so the judge is graded on the **full unfiltered set**. If rung 1 filtered, rung 4's marginal contribution would not be attributable to rung 4.

> **The measured runs below did not use this order.** Every figure on this page
> was taken with rung 4 applied directly to [[r0]] mode A output, with no [[r2]]
> and no [[r3]] upstream. The rung as specified — judging a corrected, voted
> answer — has not been run. See Open.

## Input boundary

- May read `checks["r1_verdict"]` and `checks["r1_reason"]`. **Nothing else from `checks`.**
- Feeding the judge `checks["meddra_term"]` leaks the answer key — that table is the answer key's inventory.
- Post text from `sources[doc_id]`, never `docs`.

## What to write

- A judgement into `checks`, e.g. `checks["r4_verdict"]` and `checks["r4_confidence"]`.
- Whether it moves the zone is a **manifest choice**, and the same argument as rung 1 applies: a judge that routes confounds the rungs above it. Default to recording, and let [[r5]] act.
- Temperature 0, per `manifest.model.temperature`.

### The two questions, counted apart

| field | question |
|---|---|
| `span_ok` | is the quoted text really a reported reaction? |
| `code_ok` | is this code right for it? |

**Never pool them.** The v1 report emitted one pass/fail per record and
concluded the judge always agreed with [[r1]] — a null result. Split apart, the
two channels behave in opposite directions and the pooled verdict was hiding it.

## Ledger

One row per record, `rung=4`: real `tokens_in`/`tokens_out`, `api_calls=1`, per-call `latency_ms`, `outcome="judged"`.

Parse failures **cost tokens and produce no judgement**. They must appear in the
cost column and be excluded from every rate, with the denominator stated. Cost
per usable judgement on the 40-doc run: 908 tokens. Per record offered: 515.

## Measured — dev split, 40 docs, judge `llama3.2:3b`

    span really a reported reaction   ok   3   not  93
    code right for it                 ok  83   not  13
    pooled fail  96 (100%)
    tokens 87130   265.18s

## Gold control — 395 records

226 gold reaction mentions mixed with the 169 model records and judged in one
pass, so [[r1]] splits the set (ACCEPT 76 / BAND 153 / REJECT 166) and both
questions have known ground truth on each side.

| | gold (correct by construction) | model output (0/105 codes correct) |
|---|---|---|
| judged | 95 | 96 |
| `span_ok` | 3 — **3%** | 3 — **3%** |
| `code_ok` | 87 — 92% | 83 — 86% |

**Both channels are constants.** The judge fails the annotators' own spans at
exactly the rate it fails the model's. It passes valid codes and fabricated ones
six points apart on n≈95 each — about 1.4 standard errors, no detectable
discrimination. The judge is not reading its input.

Run: `PYTHONPATH=. python3 scripts/r4_gold_control.py`, ~10 min.

### Agreement is a property of the set, not the judge

Because the judge fails everything pooled, its agreement with [[r1]] equals
[[r1]]'s REJECT share of whatever set it is handed:

| set | r1 REJECT share | reported agreement |
|---|---|---|
| 5 docs | 9/9 | 100% |
| 40 docs | 94/96 | 98% |
| mixed control | 94/191 | 49% |

Same judge, same behaviour, 51 points of movement. **Do not report an agreement
figure for this rung without the composition of the set it was computed on.**

### Availability is input-dependent

Parse failures run **58% on gold (131/226) against 43% on model output
(73/169)**. The records that parse are not a random subsample, so every rate
above is conditioned on the judge having been able to answer at all. Do not
quote the pooled 52%.

`llama3.2:3b` at this failure rate has an availability cost before it has an
accuracy one, and the cost belongs to the judge, not the extractor.

## Bug — the constancy guard is binary

The report suppresses its agreement figure when [[r1]] returns a single verdict,
on the correct grounds that agreement with a constant measures nothing. At 5
docs it fired. At 40 docs **two BAND records** made the set non-constant and
`agree 94 (98%)` printed — a number that is pure artefact.

The guard needs a **minority-class threshold**, not a constancy check. The gate
in `scripts/r4_gold_control.py` has the correct form: refuse when the minority
class is under 10% of the set.

## How you will know it works

- **On the gold control every record is correct**, so a judge that rejects any of them is producing a false rejection — the same error-floor logic [[r1]] was tuned with. That is the cheapest first test, and it needs no scorer.
  - **Measured: it rejects 92 of 95.** The false rejection rate on known-correct spans is 97%.
- Agreement with [[r1]]'s verdict is a sanity check, not a result: the two should disagree, or the judge adds nothing.
- The measurement that matters is errors prevented per extra call.
  - **Measured: zero errors prevented, 87,130 tokens.**

## Resolved

- **A judge that only ever agrees is worth reporting as a null result.**
  Confirmed, and the mechanism is sharper than expected: the judge does not
  agree with [[r1]] — it returns a constant, and *apparent* agreement is
  whatever share of the set [[r1]] happens to reject. See the table above.

## Open questions

- Does the judge see the candidate code's vocabulary terms? That is a lookup, which makes it a different intervention from a bare judge — declare it in the manifest if so. **Currently it does not.**
- **The specified order has not been run.** Rung 4 on post-[[r2]], post-[[r3]] records is the experiment this page describes and it remains untested. Given [[r2]] rescued 0 and [[r3]] changed 3, the input set would be nearly identical — but "nearly" is an assumption, not a measurement.
- Both channels being constant means this rung contributes nothing at any price. Whether a larger judge discriminates is untested.
- The 6-point `code_ok` gap is not significant at this n and must not be reported as discrimination.
- `checks["r4"]` is written for [[r5]] to consult; [[r5]] does not yet read it.
