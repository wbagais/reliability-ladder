The Reliability Ladder

Which reliability layer buys the reliability, and where it stops being worth paying for. Two people, three days.

Status — read this first The numbers exist. All seven rungs have been measured on the 40-document dev split of CADEC v2, with granite4:micro-h as extractor and llama3.2:3b as judge, against SNOMED CT-AU AU1000036_20260731 on a local GPU. Two gold controls have been run (rung 5 abstention, rung 4 judge), and the full ladder has been run end to end in the specified order [0,1,2,3,4,5,6], reproducing every standalone figure — so no rung interacts with another.

Headline: four reliability layers, zero correct codes. Rung 0 produces 169 mentions at span F1 0.543 and 0 of 105 correct SNOMED codes. Self-correction offered 158 corrections and rescued none. Voting was unanimous on 2% of its input and did not re-find the other 98%. The judge returns two constants — it fails 97% of spans whether they are the model's or the annotators', and passes 86–92% of codes whether they are fabricated or correct. Abstention withdrew 169 of 169, correctly, and inherited all of that correctness from a lookup.

This document has not caught up. Sections written as predictions still read as predictions, and several now state things known to be false — the record shape in §1, k=5 in §5, the gold count in §6, and the second-corpus claim in §9. See docs/plan-html-audit.md for the full list, docs/decisions.md for what was found and when, and docs/infoq-article-draft.md for the write-up.

1. Problem statement

Pharmacovigilance triage. Spontaneous adverse-event reports arrive from patients and call centres. Most are routine; a minority need a trained safety officer. The system reads each archived report, identifies which spans mention a medication and which mention a bodily experience, normalises each to a standard vocabulary, and routes the record — verified, abstained, or escalated to a human.

{
  "doc_id":        "PV-2026-0412",
  "drug_text":     "voltarin",            // span exactly as written
  "reaction_text": "my stomach was on fire",
  "reaction_sct":  "162031009",           // SNOMED CT — GOLD, scored strictly
  "reaction_meddra": "10013946",          // MedDRA — GOLD, ADR terms
  "check": {                              // audit trail — never scored
    "sct_exists":     true,               //   the code is real
    "sct_is_finding": true,               //   descendant of |Clinical finding|
    "lexical_match":  false,              //   span matches no term for this code
    "zone":           "BAND",
    "reason":         "colloquial_no_lexical_match"
  }
  "evidence_span": [11, 19],              // offsets into doc_id — mandatory
  "confidence":    0.71
}

The system reports what a report says. It does not assess whether a drug caused an effect. Both words in the name are load-bearing: triage is the routing, and the source-grounding constraint below is what keeps the output an annotation rather than a clinical claim.

1.1 Five constraints that make this safe to publish

This project ships deliberately unreliable systems — rungs 0 to 2 are supposed to fail. A public repo of runnable drug-safety-shaped pipelines with an advertised failure table invites misuse. Disclaimers don't fix that; design constraints do.

ConstraintWhy it works
1. Fixed archived corpus onlyNo free-text input path anywhere in the repo. There is no box to type into, so nobody can point it at their own medication list. Missing interfaces stop misuse; warnings do not.
2. A record without a span is invalidEvery output resolves to a character range in a specific archived report. Enforced in the schema, so an output that is not a citation cannot exist. Doubles as the Rung 1 grounding check, so it costs nothing.
3. No causal link assertedDrug and reaction mentions extracted independently. Never emits "drug X causes Y". The corpus annotations don't either, so this also keeps you faithful to gold.
4. Aggregation is out of scopeCounting reaction frequency across reports is what turns annotation into a safety signal. Name it out of scope. A stated boundary makes the paper stronger.
5. Abstention escalates, never discardsThe system surfaces candidates for a human and has no authority to rule anything out. Makes Rung 6 the design intent rather than a bolt-on.

2. What rung 1 actually does

Rung 1 is a validation gate, not a router. It cannot tell you a code is right — nothing deterministic can, because the code is not in the source text. It can tell you a code is wrong, and it does that at no model cost.

#CheckNeedsCatches
1Schema validnothingMalformed output.
2Span grounding — does the quoted text sit at those offsets?nothing, a string compareFabrication. Cheapest check on the ladder; fires before any lookup.
3Negation — is the mention explicitly denied?a cue list, no vocabulary"so far no gastric problems" extracted as a reported reaction. Common in patient reports and cheap to detect.
4Code exists in SNOMED CT or MedDRAvocabulary lookupHallucinated codes. Binary — no similarity score.
5Semantic type — descendant of 404684003 |Clinical finding|?vocabulary hierarchyReal codes in the wrong slot — a procedure where a finding belongs.

Two outcomes only: REJECTED with a reason code, or PASSED VALIDATION and carried on. Passing validation is not a claim of correctness.

MEASURED 2026-08-22 — this claim did not survive the corpus. Three outcomes in the implementation: REJECT, ACCEPT (the vocabulary uses these very words) and BAND (plausible, unverifiable). Two cannot express BAND, and BAND is where 57% of even a perfect answer set lands — that fraction is the bill the paid rungs work through. Rung 1 also now judges without routing by default: a filtering rung 1 makes every rung above it unattributable. See docs/decisions.md.

The negation check earns its place on real text

MEASURED 2026-08-22 — this claim did not survive the corpus. As a rejection this costs 427 gold-correct mentions (4.7%). CADEC annotates a mention regardless of polarity — the example below, “so far no gastric problems”, is annotated in ARTHROTEC.1 as an ADR coded 162076009 — and NegEx scope misfires on forum prose. Negation is now an audit flag: the cue still fires and is still reported, but it does not reject. See docs/decisions.md.

From an actual reporter: "I feel a bit drowsy & have a little blurred vision, so far no gastric problems." A model will happily extract gastric problems as a reported reaction. It is explicitly denied. No vocabulary is needed to catch that — a cue list and a window around the span is enough, and it costs nothing.

Log it as its own rejection reason. Negation errors are a distinct class and worth reporting separately, because a system that gets codes right but polarity wrong is dangerous in a way an F1 score hides.

2.1 What rung 0 is allowed to do — settle this before you build

The code is never in the source text, so rung 0 has to produce one from somewhere. Two options, and they measure different things:

OptionWhat "bare LLM" meansWhat you learn
A · recall only
recommended		The model emits a code from memory. No tools, no lookup.How reliably a model recalls clinical codes unaided. Expect a high hallucination rate — and that is the point: it makes rung 1's rejection rate meaningful.

3. The five objectives

Confirm these with your partner before building — they are my inference from the brief, not your group's decision. They are now hard-coded into the Triage desk, so changing them means changing the app.
#ObjectiveMeasured by
1Does each rung buy reliability?Strict and relaxed F1, coverage, per rung
2What does each rung cost?Tokens per record, latency p95, records routed to a person — three measures, never fused into one
3Where does it stop being worth it?Marginal $ per prevented error against assumed error cost
4Does any rung make things worse?Over-escalation, self-correction regression, judge false-approval, consensus-on-wrong
5Does the answer depend on difficulty?Rung 1 rejection rate and the marginal costs, messy corpus vs clean prose

Objective 4 is the one nobody publishes, and the Triage desk measures it live — when you close a report that never needed a human, it counts.

4. Dataset and sources

Primary: CADEC

CSIRO Adverse Drug Event Corpus. 1,250 patient posts from AskaPatient, in two groups by active ingredient (Diclofenac and Lipitor). Annotation ran in two stages — human entity identification, then terminology association — with guidelines, multi-stage annotation, inter-annotator agreement and final review by a clinical terminologist. ~6,754 entity mentions across five types.

MEASURED 2026-08-22 — this claim did not survive the corpus. v3’s sct/ files carry 9,111 mentions — ADR 6,318, Drug 1,800, Finding 435, Disease 283, Symptom 275. See docs/decisions.md.

Two corpus facts that change the design — verify both at 0:00 1 · CADEC codes reactions, not drugs.

MEASURED 2026-08-22 — this claim did not survive the corpus. v3’s sct/ files code 1,657 of 1,800 drug mentions, mostly to AMT product concepts. Licence — read before you plan the repo CADEC is released under the CSIRO Data Licence, not Creative Commons. It grants a royalty-free, non-exclusive, non-transferable licence to use the data for non-commercial purposes only; the corpus paper states the data is for research purposes only.

Three consequences: (a) you cannot redistribute the corpus — not in your repo, not in a release asset, not in a notebook output; (b) both of you must accept the licence individually at H0, since it is non-transferable; (c) if this work is ever commercial, the corpus is out and you need a different dataset. Note also that CSIRO retired this licence for new collections in July 2021, so older collections like CADEC still carry it while newer ones may not.

4.1 Vocabularies — the second data source

The agent has to produce codes, so the vocabularies are input data, not just a checking convenience.

VocabularyCoversAccessRole here
SNOMED CTAll clinical concepts — ADRs, symptoms, diseases, findings BioPortal API (free, no login to search) · EBI OLS4 · SNOMED browser API. Full releases need a licence, free in member countries. The scored target. Also supplies the existence, semantic-type and lexical checks in rung 1.
MedDRAAdverse drug reactions specifically — the regulatory standard Hosted on BioPortal. Full releases are subscription-based. Secondary gold for ADR mentions. Agreement between SCT and MedDRA is itself a signal.
AMTDrug names (Australian Medicines Terminology)— Out of scope. Drugs are span-checked only; no drug code is scored.
Verify vocabulary access at 0:00 — this is the new critical-path dependency Rung 1 needs a code-existence lookup, and where it comes from decides whether rung 1 works at all.

MEASURED 2026-08-22 — this claim did not survive the corpus. A local RF2 release removes this dependency rather than mitigating it — no key, no rate limit, no network in the measurement loop. It also matters which: an OLS4-backed exists() reports 23.9% of CADEC gold as nonexistent codes (7.5% retired, 16.4% AU-extension = 100% of drug mentions, which are AMT). A rejection rate is not comparable across backends. See docs/decisions.md.

Try in order: BioPortal API (free, hosts both, no login to search) → EBI OLS4 → a local release if your institution holds a licence.

Do not build the check from CADEC's own gold codes. That is leakage — the check would accept exactly the codes the answer key uses and reject everything else, and your rung 1 numbers would mean nothing.
Version-pin the vocabulary SNOMED CT and MedDRA both release twice a year; codes are added and occasionally inactivated. Record the release version in the manifest at 0:00, exactly as you would a model ID. Without it a rung 1 result is not reproducible.

Why rung 6 is a rung, not a prompt instruction "Tell the model to escalate when it is unsure" is rung 5, abstention — the system declining. Rung 6 is a person actually resolving the record. Fold them together and you lose four things you cannot recover afterwards:

1 · The cost. How many records reach a person, and how long each takes. That is one of your three cost measures and it exists nowhere else.
2 · Whether the human is right. Agreement with gold, and disagreement between your two reviewers. Humans are not an oracle and the number is publishable.
3 · Over-escalation. Records sent to a person that no person needed to see. If escalation is just the model saying "I don't know", you cannot measure how often it says that wrongly.
4 · The ceiling. R6 tells you what is achievable at all. Without it you cannot tell a hard record from an unfixable one.

There is also a circularity problem: a model's self-assessed "I'm unsure" is the very signal this project shows to be unreliable — rung 0 reported 0.66 confidence on a fabricated drug. Trusting the model to know when to escalate is trusting the thing under test.
Do not renumber — make order a config value instead The rung numbers come from the brief and are shared with anyone else running this ladder. Renumber them and your results stop being comparable to the brief, to other groups, and to your own earlier iterations. Rung ID is identity; execution order is configuration. 
manifest.json
  "rung_order": [0, 1, 2, 3, 4, 5, 6]
The pipeline reads the list; results.csv stays keyed by rung ID. Two payoffs: no confusion in the code, and order becomes something you can test. Re-running with [0,1,2,3,5,4,6] — abstention early — costs one config change and tells you how much the ordering claim is actually worth. That is a cheap ablation and a better contribution than asserting the order is optimal.
Numbering is not execution order Abstention must run last — abstaining before you've tried correction and voting throws away recoverable records — so it is numbered last, as rung 3. Rung IDs equal execution position: 0 → 1 → 2 → 3 → 4 → 5 → 6. They were renumbered on 2026-08-23; measurements dated earlier use the old IDs, and the mapping is in docs/decisions.md.

The methodological trap — the crux Rungs 1, 3, 4, 5 make answers more correct. Rungs 2 and 6 make the system refuse or defer — buying safety by giving up coverage. A single F1 cannot compare these, and any paper that tries has a hole in it.

Fix: report everything on a risk–coverage curve and compare at matched coverage. Accuracy rungs move the curve down; abstention rungs move you along it. Deserves its own section, and is probably why nobody has cleanly measured this.
Why there is no dollar figure A single $/100 needs a price table that shifts under you, and it silently fuses three costs that are not interchangeable. Keeping tokens, latency and human reviews apart forces the honest question: would you rather spend tokens or human attention?

It also removes a fake precision. There is no single optimal rung — there is a marginal exchange rate at each step, and the reader supplies their own threshold. Rung 6 is priced in a currency the other rungs do not use at all, which is exactly why it must not be collapsed.

6.2 Statistical discipline

  • Paired bootstrap, 10,000 resamples, for the CI on adjacent-rung differences. Report Δ with CI. If a CI crosses zero, say so — "Rung 4 did not measurably help" is publishable.
  • McNemar's test for paired correct/incorrect.
  • Test split touched once per rung. Prompts, thresholds and judge calibration on dev only. Write this rule down Day 0.
  • Fixed seeds identical across rungs. Freeze the manifest: corpus version, SNOMED and MedDRA release versions, model IDs, prompt hashes, date.

6.3 Contamination

CADEC is public and from 2015 — almost certainly in pretraining. Three responses, all strengthening: state it plainly in limitations; note it inflates R0, which makes the ladder's gains look smaller, so your conclusion is conservative; validate on CADEC v2 (2024), whose drugs are absent from v1.

7. Iterations and the hour budget

The cut axis — decide this before anything else Cutting rungs changes the question. Cutting sample size only widens the intervals.

Stop at rung 2 and you cannot answer "where does it stop being worth it", because the crossover might sit at rung 3 and you would never see it. The shape of the ladder is the contribution, so all seven rungs are in iteration 1 — thin, on a small sample, with honest error bars. Depth arrives in later iterations.

8.2 How the code is organised

Not a division of labour — a division of mental models. Each cluster below answers one question, and holding one at a time is what keeps the contracts between them honest. Whole files stay whole, which is also what keeps merges cheap.

AreaCoversFilesMental model
The spineEverything deterministic: ledger, registry, zones, abstention, integration. ledger.py · registry.py · rungs/r1.py · rungs/r5.py · run.py "Records flow through zones and every transition gets logged." No prompts, no model calls.
The model surfaceEverything that talks to a model, plus scoring. score.py · rungs/r0.py · r2.py · r4.py · r3.py · prompts/ "Given records and sources, return better records." No ledger internals, no zone logic.
The contractsSchema, the rung interface, rung 6, analysis. schema.py · rungs/r6.py · manifest.json · docs/decisions.md Agree the change before making it.
Five rules that keep the layout working 1 · schema.py freezes after step 3. It is the contract every rung reads. If it must change, everything stops and the change is agreed first — a silent schema change is the one thing that costs an hour you do not have.

2 · No rung reaches into another rung. A rung sees its records, its sources and its cfg. It never imports a sibling and never picks its own model — run.py resolves that once, from the manifest.

3 · Integrate often. Four merges of fifteen minutes beats one merge of an hour.

4 · Append, never reorder. New ledger fields go on the end. New rungs go in new files. Reordering a dict or a CSV column is a guaranteed conflict for zero benefit.

5 · manifest.json is append-only too. It is the file most likely to be touched from two directions at once, which makes it the most likely conflict in the repo.

12. Repository hygiene

  • No inference entrypoint on free text. The runner takes a corpus split identifier, not a string. Modifying the code to change that is a meaningful barrier and an explicit choice.
  • README states intent up front: a measurement study of reliability layers. Rungs 0–2 are research artifacts with deliberate failure rates, unfit for operational use.
  • Ship the manifest — corpus version, vocabulary releases, model IDs, seeds, prompt hashes. Reproducibility and honesty are the same file.
  • Respect the corpus licence — this one has teeth. The CSIRO Data Licence is non-commercial and non-transferable, so the corpus cannot appear anywhere in your repo: no data/ directory, no release asset, no committed notebook with post text in the output cells. .gitignore the corpus directory on day zero, and strip notebook outputs before committing.
  • Ship a fetch script instead. A short get_data.py that points at csiro:10948 and tells the user to accept the licence themselves. Reproducible without redistributing anything.
  • Quote sparingly in the paper. Short illustrative snippets are normal academic practice; bulk post text in an appendix is redistribution.

Technical architecture

What runs where, what is committed, and what must never leave the machine.

The constraint that shapes every decision below The corpus is licensed non-commercial and non-transferable, with no redistribution. It cannot appear in the repository, in a container, in a deployed app, or inside a committed notebook output cell. Everything else follows from that: the benchmark runs locally, and only derived results are ever published.
The gap in the control that constraint depends on scripts/preflight.py is the licence gate, and it scans tracked files only. An unzip -d data/ once put both corpus archives in the working tree, untracked and unignored, and preflight would not have caught it — the staging step is the one place the gate cannot see. .gitignore is now data/* with an explicit !data/splits/ exception, and git status --short before every git add -A is the manual half of the control.

1b. Observability

Three layers, and only the first two produced findings.

LayerWhat it recordsWhy
Run provenanceCompute backend, SNOMED release, corpus version, model, split, temperature, rung orderDeterminism is bounded by the hardware — the same model and seed produced 176 mentions on CPU and 169 on GPU. Two runs are not comparable without this.
LedgerOne row per record per rung: tokens, calls, latency, outcome, denominator, evaluableThe last two are the ones nothing else models. A rate is meaningless without the set it is over, and could not run is a third outcome that must never collapse into pass or fail.
OTel exportThe ledger as OpenTelemetry spans, off unless LADDER_OTEL=1Optional and off by default: every measured figure was taken without it, and an observability layer that changes what it observes would be an odd thing to ship in this project. Points at any OTLP collector.
Why the ledger is custom and not a platform The open-source LLM tracing tools all model the same unit — the call: prompt, response, tokens, latency, and usually an LLM-judged quality score. None of them models a denominator, and none represents the composition of a comparison set. Rung 4's agreement figure moved 100% → 98% → 49% across three sets with no change in judge behaviour; that movement is invisible in every tool evaluated, because it is not a property of any call. Several also ship LLM-as-judge scoring as the default quality signal, which is the mechanism this project measured returning two constants.
