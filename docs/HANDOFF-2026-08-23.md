## Findings — all measured, all new

### 1. Pooled drug/reaction ratios describe neither

| pooled | drugs | reactions |
|---|---|---|
| 11% codes inactive | 46.8% | **6.2%** |
| 23.9% backend disagreement | 100% | **5.9%** |
| 43.1% ACCEPT on gold | 76.0% | **35.0%** |

Drug names appear in patient text as printed; reactions are in the reporter's
own words. **The headline claim changes: 43% pooled is 35% on reactions.**

### 2. Check order determines the reported diagnosis

`r1.zone()` returns on first failure. On the dev split, mode A model output:
verdict table said `span_ungrounded 172`, `code_unknown 3`. True set:
`code_unknown 164`. **172 of 176 failures hidden.**

The offset flag ablation is the cleanest demonstration: identical model output,
identical checks, `span_ungrounded 162→0` and `code_unknown 4→155`, while the
full failure set stays invariant at 163.

**On all 9,111 gold mentions the two sets are identical** — gold spans ground by
construction, so the bias is invisible in the regime the validator was tuned in.

Fixed by `all_reasons()` in `r1.py`: every check runs into `checks["r1_audit"]`.
`zone()` untouched, 93 tests still pass.

### 3. A check that cannot run gets reported as one that passed or failed

Five independent instances: `--live` self-comparing (A found this),
`snomed_backend` inert, `vocab is None` returning BAND, my script counting
exceptions as disagreements, rung 4's agreement metric on a constant set.
`vocab is None` now raises unless `allow_no_vocab`.

### 4. Determinism is bounded by the hardware

Same model, seed 0, greedy: **176 mentions on CPU, 169 on GPU.** Three GPU runs
byte-identical. Reproducible within a backend, not across one. Backend must be
recorded like the SNOMED release.

### 5. Four reliability layers, zero correct codes

Dev split, 40 docs, granite4:micro-h, GPU:

| rung | intervention | cost | correct codes |
|---|---|---|---|
| 0 A | baseline | 19,354 tok | **0/105** |
| 0 B | tool prompt | 20,431 tok | **0/96** |
| 3 | self-correction | 72,539 tok | **0/105** |
| 5 | voting k=3 | ~3x rung 0 | **0** (all fabricated) |

Span F1 **0.543** (P 0.683 / R 0.451). The model finds roughly half the
reactions and codes none of them.

**Each layer fails in a way that looks like success:**

- Mode B halves rung 1's rejection rate — entirely through 59 null codes.
  `honoured_tool` never True; `vocab.search` runs AFTER generation, so the
  A/B contrast measures **prompt wording, not tool access**. Rename it or build
  a real loop; do not publish the current framing.
- Rung 3: **158 offered, 0 rescued, 158 declined.** Not one `reasserted`. Told a
  code does not exist, the model never proposes another.
- Rung 5: 3–0 unanimous on codes the greedy pass never produced, all nonexistent.
  Temperature relocates the model to a *different* confident answer rather than
  spreading it. **38% of mentions were not re-found by any sample** — extractor
  instability, not disagreement.

The article's claim: **a model lacking the underlying knowledge cannot be made
reliable by any wrapper, and every wrapper produces a metric suggesting
otherwise.** The deterministic checks were the only thing that caught it.

### 6. The BAND zone, demonstrated

The only 3 records rung 1 did not reject, all exist / active / finding /
`lexical_match` False, all wrong per gold:

    LIPITOR.401#3   60551006  'loss of balance'
    LIPITOR.935#1   39249009  'constipitation'
    LIPITOR.935#2   39249009  'no control over urination'

One code for two opposite conditions in one document. Rung 1 validates codes in
isolation and cannot notice. **A deterministic checker cannot be a scorer.**

### 7. A gold defect, with evidence

`data/cadec/data/cadec/sct/LIPITOR.511.ann` line 3 has `20070731` — a date —
where an SCTID belongs, inside an `all_of`. Survived the v1→v2 revision. Handle
as a documented gold-defect list, never a silent filter.
