The Reliability Ladder · article raw material

The ladder, measured to the top — then audited

Seven reliability layers — validation, self-correction, voting, a judge, abstention, a human queue — measured one rung at a time, then run cold, once, on held-out data. Then audited as a stack, which is where the strongest results turned out to be: three of the paid rungs are wired to nothing, and the metric cannot see the bug. This is the layer underneath the article — the numbers worth quoting, and how they were arrived at.

01Thesis

The thesis, in one paragraph

Every LLM agent is roughly 10% model and 90% harness, and that harness gets built by intuition: teams stack retries, validators, judges, voting and human review because each one sounds like it should help. The seven layers are known. What nobody publishes is the measured trade-off per layer — what each buys, in which currency, and where it stops being worth paying for. That curve is the contribution; everything else exists to keep it clean. Having measured it, the answer is not the one the premise expects: the ladder made errors visible, not fewer. The layers that survive are the free deterministic check and the person; the paid model rungs, in composition, moved nothing they could not also have broken — and two of them turned out not to be wired to anything at all.

Everything here is measured on CADEC — patient-reported adverse-event posts, normalised to SNOMED CT. The deterministic gate was characterised first, against the gold standard and planted errors, before a single model call; the model-facing rungs were then measured through five dev phases; and on 2026-08-26 the whole ladder ran cold, in order, on the 60 held-out test documents, under a frozen configuration, exactly once. Nothing was re-run after the numbers were seen. The cost curve this page once listed as “still to come” is now its first finding.

A gate's leniency setting decides whether it protects you or lies to you

19.0% of planted near-miss codes are put in ACCEPT by the intuitive lexical setting — records the validation gate actively vouches for. The strict setting puts 0.1% there.

Rung 1 sorts each record into REJECT (provably wrong), ACCEPT (the vocabulary uses these very words) or BAND (plausible, unverifiable). The ACCEPT/BAND divider is a string comparison between the quoted patient text and SNOMED's terms for the predicted code, and it has one obvious knob: exact equality, or token containment.

Containment is the intuitive choice. Patients write “bit drowsy” where SNOMED says “Drowsy”; being strict looks pedantic, and being lenient lifts the share of a perfect answer set that rung 1 settles for free from 43.1% to 54.5%.

Then we planted near-miss codes — a real, active clinical finding sharing its head word with the right one, which is the confusion a normalisation model actually makes — and asked what the gate did with them.

Lexical settingNear-misses caughtNear-misses put in ACCEPTACCEPT lane on gold
contained0.1%19.0%54.5%
exact0.1%0.1%43.1%

Neither setting catches near-misses — deterministic checks can't, and the plan said so. But the lenient one endorses one in five, because the span text is a subset of the wrong concept's term. It doesn't fail to protect you; it hands you false confidence.

We changed the default to exact and paid eleven points of free settlement for it. The rule worth writing down: for any validation gate, measure the permissive setting's false-vouch rate on planted near-misses before you ship it. “Be lenient with colloquial input” is a reasonable instinct that here converts a gate into an endorsement machine.

Deterministic checks are not “pretty good” at their job. On the classes they are designed for they are exact, at zero model cost — and on the one class that matters most, a real, well-typed, wrong code, they are blind by construction, because the code is not in the source text and nothing mechanical can put it there.

That reframes the ladder, and it beats “a stack of improvements”: rung 1 is a free, exact filter for a specific set of failure modes, and everything above it is a paid resolver for the one class the filter cannot see. The economic question is not whether rung 1 helps — it does, for free — but what the paid rungs charge for the residue.

Over half of a perfect answer set is unverifiable

Worth stating as a planning tool: run your deterministic layer over your answer key first — the BAND fraction is your bill.

Asking a model to recall a nine-digit code is broken, not weak

0.018 F1 when the model states the SNOMED code from memory — vs 0.171 for naming the concept, at more tokens. Retrieve-and-pick: 0.209.

Rung 0 is a three-step prompt study with identical scope; only where the code comes from changes. The memory step is ten times worse than the naming step, costs more (44.0k vs 36.1k tokens), and is the only step that fails to parse (5 of 40 documents). The one thing a language model cannot do — recall a nine-digit identifier — is also the most expensive way to ask. An abstention hatch reduces fabrication without removing it: allowed to answer null for unknown ids, the model did so 12.4% of the time — and still emitted a nonexistent code beside a correct label.

And the retrieval that fixes this is not presentation-neutral: alphabetising the candidate menu — changing nothing but the order — cost 10–12 points of coding accuracy at byte-identical detection. Small models anchor on early slots; the retriever's best-first ranking is doing real work.

Voting can only shuffle what is below it — and its numbers are samples

Rung 3 resamples each document at temperature and takes majorities. As first built it destroyed verified answers: votes matched by exact span key never aligned across resamples (206 of 240 records got no vote), and a “majority” of one — the only sample that re-found a mention — overwrote a vocabulary-verified code with its opposite. Three repairs, each test-first: match votes by span overlap one-to-one, draw every sample through rung 0's own configured path so votes come from the distribution being voted on, and require at least two sightings before a change.

After repair, on dev: hallucinated overwrites gone, zero correct codes destroyed, +5 net correct — for 2.6× rung 0's tokens. On the one test draw: 8 records re-found, all 8 wrong, correct count unmoved. A voting rung's contribution is a sample, not a property — cite the run id with every number, and price the draw honestly: it is the most expensive rung on the ladder.

The judge measured, the better judge rejected, and the signal that lived in an accident

167/240 records left unjudged by the domain-adapted 7B judge that was installed to replace the 2B one. Every verdict it did parse was “fail”; its confidence was a flat 0.0.

The judge must be a different model family from the extractor, and the only local option judges the wrong way round: 2B judging 20B, stated with every rung 4 number. The obvious fix — a domain-adapted 7B — was installed, harness-repaired twice, and rejected on measurement: it answers end-of-sequence after { on prompts past ~430 tokens. Domain adaptation does not buy instruction-following.

The sharper finding came from re-judging the incumbent through a repaired prompt path: an accidental duplication — the post pasted twice — turned out to be load-bearing. With it, the judge's pass/fail correctness split was 28.0% vs 15.6%; without it, 25.4% vs 23.6% — no separation. Same lesson as the menu order: for small models, prompt form is part of the measurement, and a signal that lives in an accident is not a signal an article can stand on. The duplication stayed fixed; the test-split verdicts carry the caveat.

Abstention's bill is countable — and a person could pay it down to 0.99

242/314 records routed to a person on the test run — the headline cost of rung 6, kept as a count, because minutes here are declarable, not measurable.

Rung 5 withdraws every answer the stack could not corroborate; rung 6 is what happens to the queue. Two measurements make it legible. Its composition: rung 5 withheld 45 exactly-correct answers on test (86 by overlap) — the price of taking errors per 100 from 59.6 to 3.8. And its ceiling, measured on dev with an oracle desk (gold-derived resolutions, refused on the test split by design): a perfect reviewer takes shipped F1 from 0.131 to 0.444, and coding accuracy on matched spans from 0.291 to 0.990 — with detection unchanged.

Read that pair carefully. After a perfect code-picking human, the entire remaining gap is span boundaries, which neither the desk nor any code-level rung can fix. The next rung worth building is boundary repair — and this number is how we know, which is the real use of a ceiling.

Retrieval's gain decomposes — and the decomposition inverts with k

The dense retriever beats the lexical one 86.1% to 61.8% recall@20 — but the two also search different corpora, so the headline confounds two changes. Running the lexical scorer over the dense corpus separates them: at k=20 the gain is +3.3 from the corpus and +21.0 from dense scoring. At k=1 it inverts — +29.1 corpus, +15.2 scoring: filtering to the right semantic types is what clears the top slot; better scoring is what fills the rest of the menu. Both retrievers are kept, because a recall number under one is only interpretable next to the other.

03Audit
Rungs 1-6, audited on 2026-08-28. Everything here is dev-side: the test split was spent once and is not re-opened.

Ask what reads what

Everything above measures a rung. This band measures the composition, and it is where the strongest negative results are. Each finding was demonstrated on real run artifacts before a line of code was changed.

Every deferral in the ladder terminates in a field nothing reads

3 → 0 three rungs defer their action to rung 5. Rung 5 reads none of their fields.

Rungs 2, 3 and 4 each decline to act on their own evidence, on an argument this project made loudly and correctly: a rung that routes confounds every rung above it, so a rung should record its judgement and let the rung that owns coverage act. Each names rung 5, in its own docstring.

RungWritesSays
2 · self-correctionchecks["r2_declined"]“rung 5 owns abstention and reads checks['r2_declined']”
3 · votingchecks["r3_unanimous_none"]“EVIDENCE for rung 5, not an action here”
4 · LLM judgechecks["r4_verdict"]“record … and let rung 5 act”

r5.decide() reads the zone, r1_verdict, r1_reason and rec.confidence. Its entire configuration is {tau, abstain_zones, abstain_on_reject}. A repo-wide search finds no consumer for any of the three fields outside the rungs that write them and one diagnostic script. In composition the ladder is one rung: rung 5 routes on rung 1's free lexical verdict and nothing else.

No test could have caught this, because every rung does exactly what its own docstring promises. Each was reviewed, tested and measured alone; the hole is between them. It is only visible if you stop asking “does this rung work” and start asking “what reads this rung's output” — a question with no unit-test shape. For every field your pipeline writes, grep for its readers, and treat a field with no reader as a rung that is not in your pipeline no matter what it costs to run.

A fix three rungs down silently disabled two rungs up

5.1% → 0.4% rung 1's rejection rate, after an accuracy fix at rung 0. Rung 2's trigger set went with it.

Rung 1 rejected 5.1% on the held-out test run, every one schema_invalid — rung 0 emitting an unlocated (-1,-1) span for a quote it could not find. Rung 2 fires on a rejection that yields a statable fact; schema_invalid yields none, so rung 2 fired zero times in the whole run. Then rung 0 got better: a later span filter drops exactly those records at rung 0. Rung 1 now rejects 1 of 248, and rung 2's trigger set holds 1.

Nothing is broken. Both rungs still pass every test, still log every row, still report honestly. Their input was removed from underneath them, and no per-rung test and no per-rung report could show it — a rung with nothing to do and a rung doing nothing look identical from inside. If you tune the bottom of a pipeline, re-measure the top; the layers you are proudest of are the ones most likely to have quietly become no-ops.

The check a validation layer was built for can become unreachable

0 of 248 times rung 1's headline check — “does this code exist?” — fires. label_verified is true 232 of 232.

The existence check was tuned in 2026-08-22 against a rung 0 that recalled codes from its weights, where 164 of 176 emitted codes did not exist at all. It is the reason the rung exists. It now fires zero times — confirmed through the unmasked reason table, so this is not the first-failure ordering bias. The cause is architectural: rung 0's shipped step picks from a dense-retrieved menu of real SNOMED codes and resolves names through the same table, so the model can no longer emit a code that does not exist.

Two more went with it: sct_active is true for all 232 coded records and sct_outdated false for all 235. And label_verified — “did the model name the concept it coded?”, added because 82249009 is real, active, and means |California chicken| — is true 232 of 232, because the retrieval menu shows the code and its vocabulary label together. The model's label is the vocabulary's own label by construction. A validation layer is calibrated against a generator; when the generator's failure mode moves, the layer does not follow it, it just keeps passing.

The headline metric is blind to the defect the ladder exists to prevent

0.0000 change in F1 from fixing a record that shipped marked VERIFIED on a warrant for a code it no longer had.

Across the two archived full-ladder runs the vote changed 25 and 30 codes, and all 55 carried a verdict about a superseded code. The metric the ladder is optimised against is structurally blind to the failure the ladder was built to prevent, which is a reason to be suspicious of any reliability layer justified on F1 — including every layer in this project.

A dial nobody could have turned

{1.0, 0.99} every value rung 0's self-reported confidence takes on dev. Rung 5's tau has been 0.0 for the life of the project.

Rung 5 has a confidence threshold, a risk-coverage sweep written to tune it, a manifest note recording that it is tuned on dev, and a declared abstention reason low_confidence. It had to be 0.0: any threshold at or below 0.9 abstains nothing, and any threshold above it abstains 80–98% of the set on a number the model emits as boilerplate. low_confidence is unreachable and the sweep has nothing to sweep. An unelicited “confidence” field from an instruct model is not a measurement; it is a token the model has learned to end JSON with.

“Which configuration produced this number” needs one answer, twice over

5.9 points by which manifest.json's rung 0 sits below the baseline every recent measurement is compared against.

This project already learned this once: a model default in code and a model name in configuration disagreed, so “which model produced this number” had two answers, and the fix was to make the resolver raise rather than fall back. The same failure recurred one layer down — a set of rung 0 accuracy arms was measured, accepted, and shipped as code with their defaults off, and the manifest was never appended to.

The general form: “off by default” is a safe policy for a behaviour and an unsafe one for a measurement, because the arm you measured and the arm you ship are then different arms and nothing in the repository knows which is which. If you gate changes behind flags, make the flag's value at measurement time part of the recorded result.

What this band is evidence for

The ladder's premise is that stacking reliability layers buys reliability. Six of the seven rungs are now audited, and the honest summary is that the ladder made errors visible rather than fewer. That is worth something — every finding here exists because the harness records what each rung did — but it is not what the layers were bought for. What survives is small and specific: one free deterministic check that out-separates a paid judge, an abstention mechanism whose bill is a countable number of records, and a person. The paid model rungs, in composition, moved nothing they could not also have broken.

04Iterations
The differentiator. Most measurement pieces present the finished number; the value is in the corrections.

What we changed, and why

Rung 1 as the plan specifies it rejected 9.3% of the gold standard. A validation gate with a 9% false-positive rate does not measure a model — it manufactures errors, and every rung above inherits them. Three causes, all fixed. Then three more: rung 1 stopped filtering, one vocabulary turned out to be the answer key wearing a hat, and a second one disagreed with the first about a quarter of the corpus.

1 · The plan said negation was a free win. The corpus said it rejects 4.7% of correct answers.

Plan
Negation gets its own boxed section: a cue list and a window catch “so far no gastric problems” extracted as a reported reaction, at zero cost, logged as its own rejection reason.
Data
The check rejected 427 gold-correct mentions, from two independent causes. First, the plan's worked example is post ARTHROTEC.1, and CADEC annotates gastric problems in that very sentence as an ADR coded 162076009 — CADEC annotates a mention regardless of polarity. Second, NegEx scope misfires on forum prose: “I can't describe the horrible stomach pain”, “I can finally clean my house without pain”, “doctors deny that there is a connection between joint pain … and Lipitor”. Each negates something; in none of them is it the mention.
Change
Demoted from a rejection to an audit flag. The detector still runs and the rate is still reported — polarity is a real safety class — but under this answer key it may not reject. negation_action: "reject" reproduces the plan as written, and costs 427 mentions.
Why it matters
The cleanest example of a check that is correct and still wrong to enforce, because the ground truth encodes a different policy. You do not find this in the plan; you find it by running your check against the answer key.

2 · The semantic-type check was rejecting retired concepts, not wrong ones

Data
“Is this code a descendant of |Clinical finding|?” rejected 416 gold-correct mentions — and 413 of them for a reason with nothing to do with semantics. |Knee pain| (63 mentions), |Weakness of limb| (53), |Mentally dull| (38), |Bloating symptom| (34): all clinically right, all retired from SNOMED since CADEC was coded in 2015.
Mechanism
When SNOMED retires a concept it also retires that concept's is-a relationships. A walk over active relationships cannot place a retired concept anywhere — and “cannot place” was being read as “is in the wrong branch”.
Change
The index stores the |Clinical finding| descendant set twice: over active is-a rows (129,675 concepts) and over every is-a row ever published (177,603). finding_status() returns finding / not_finding / unknown, and rung 1 may reject only on a positive not_finding. Absence of evidence is not evidence of a wrong slot.
Residual
3 rejections in 9,111 — and all three are the check working: |Eruption|, a morphologic abnormality, coded for “Abdominal rash”; an observable entity coded for “abdominal pressure”.

3 · “Does the code exist?” is ambiguous, and the two readings differ by 11%

Data
Of the 1,046 distinct SNOMED codes CADEC uses, in the 2026-07 release: 927 active, 115 present but inactive (11%), 4 absent entirely. Reading exists as “active in the current release” rejects 6.9% of the gold standard.
Change
exists() means present in the release, active or not; inactivity is recorded as an audit fact rather than a verdict. reject_inactive is a manifest setting, because it is exactly the kind of choice that silently moves the headline number.
General point
Vocabulary drift is a measurement artefact that looks exactly like a model error. Any benchmark that normalises to a versioned terminology and does not pin the release is reporting the terminology's release notes as its model's performance.

4 · A filtering rung 1 makes every rung above it unattributable

What we had
Rung 1 rejected records and everything above it ran on the survivors — what the plan's flow implies, and what almost every “validation layer” does in practice.
The bug
If rung 1 removes the records it dislikes, rung 4's judge is graded on a set rung 1 already cleaned. Rung 4's marginal contribution is then partly rung 1's, and no care further up recovers it. The same confound runs through rungs 3, 5 and 6.
Change
Rung 1 now judges without routing: the verdict is recorded, counted and reported, the zone is untouched, and rungs 3–6 see the full set rung 0 produced. Rung 2, which runs last, is where a verdict is finally allowed to cost coverage — so the change defers rung 1's cost rather than cancelling it, and a test asserts both modes reach the same end state. mode: "gate" restores the original flow in one line.
Why it matters
Cumulative stacking is not just a questionable default for production — it is a bad experimental design, because it destroys attribution. If you want to know what a layer buys, the layers below it must not be allowed to change its input.

5 · A vocabulary made from the answer key scores 1.000 and means nothing

Setup
The plan wants MedDRA as a second vocabulary. The only MedDRA artefact available ships inside CADEC and is derived from it. Its giveaway columns — occurrences, posts, example_mentions — were deleted, which looks like it fixes the problem.
Data
It does not. The table is 666 codes, all 666 of which appear in CADEC's gold and none of which do not — the answer key's code inventory, about 3% of MedDRA's preferred terms. Deleting the columns removes the evidence of derivation, not the derivation.

Reading it
Both numbers are the leak. The check looks harmless on gold — three false rejections — precisely because the table is the gold. And it looks miraculous on planted errors, because anything outside the 666 is rejected by construction. A real MedDRA release would land somewhere in between and neither number predicts where.
Change
MedDRA is wired in properly — table, sixth check, fixture cases, probe class — and meddra_check defaults to "flag": recorded and counted in rung 1's comparison, never a rejection reason. "reject" is one manifest line away and the leakage figure prints wherever the number appears.
Why it matters
A 1.000 is the most seductive number a benchmark can produce, and this one is worthless. The general form: if your validator's reference data was derived from your evaluation data, your validator will score perfectly and tell you nothing. The tell is cheap — count how many entries in your reference list never appear in your answer key. Here it was zero.

7 · One runaway document must cost one record, and a cut-off reply is not a parse failure

Data
A dev run stopped dead for 25 minutes on a 761-character forum post — a reasoning model generating unboundedly. 90% of calls finish under 3.3k completion tokens; the tail is what makes a run unbounded.
Change
A wall-clock budget on every call, as per-model registry data, that does not raise: it returns an empty response flagged timed_out, so the run loses one record instead of its afternoon. Downstream, failures carry three labels, most specific first: timed_out > truncated > json_decode — a reply cut off by the token cap must never be counted as “the model cannot produce JSON”, and a hung machine as neither. Timeouts are filed in the cost column, not the accuracy one.
Corollary
The call cache's key must cover every generation parameter — a cache that survives a max_tokens change serves a stale result and calls it reproducibility — and a timeout is never cached: it is a property of the machine, not the question. On the final test run all three failure counters were zero, a checkable claim only because the labels exist.

8 · “Which model produced this number” must have exactly one answer

Data
Midway through, the answer had quietly become “two”: the manifest named one extractor while a code-level default substituted another whenever a manifest didn't reach the call site. Every number in that window had ambiguous provenance.
Change
The manifest is the ONE place a model is named; the resolver RAISES on a missing entry instead of defaulting; rungs never name models — they are bound by role (extractor / judge) through a single resolution function, which is also where “the judge must be a different family” is enforced rather than remembered.
Why it matters
Same shape as iterations 4 and 5: the constraints that hold are the ones with no way to express the forbidden thing. A default argument is a way to express it.

The residual 12 are 5 codes absent from the release, 4 genuine typos in CADEC's own annotations, and 3 real gold miscodings. The method is the transferable part, and it costs nothing: replay your deterministic layer over your answer key. Every rejection there is false by construction, so you get the gate's false-positive rate exactly, before any model output exists. None of the three causes would have been visible in model output — they would have shown up as a plausible-looking 9% rejection rate and been written up as a finding.

The plan's record shape encoded the claim its own safety constraint forbade

The plan's example record pairs drug_text with reaction_text in one object. Its own safety constraint says drug and reaction mentions are extracted independently and the system never emits “drug X causes Y”. Pairing them makes every output a causal claim by construction, so the unit became one record = one mention.

The same reasoning killed a second thing: CADEC's most common entity label is ADR — adverse drug reaction — which is a causal attribution made by a human annotator. Asking a model to reproduce that label is asking for exactly the claim the constraint forbids. The four clinical types collapse to reaction; only reaction-vs-drug is asked for or scored.

Article angle: safety constraints written as prose get contradicted by the data model three pages later. The ones that hold are the ones with no way to express the forbidden thing — a missing interface, not a warning.

Two more that shape the code. 1,065 mentions (11.7%) have discontinuous spans, and 45 of them quote the segments in reading order rather than offset order — a span check that compares string concatenations calls the answer key ungrounded. And CADEC's own gold fails span grounding 4 times in 9,111: rena  failure, microabrasion vs microabrasions, pain i stomach. That 0.04% is the floor the cheapest check on the ladder can never get below. Every benchmark has one; almost nobody reports it.

Process choices that paid for themselves

  • The fixture gate caught our own wrong expectation on its first run. The failing case was one we had asserted should ACCEPT: “little blurred vision”, coded 246636008. SNOMED's terms for that concept are Foggy / Hazy / Misty / Cloudy vision — it never uses the word “blurred”. Correct code, zero lexical evidence, correctly BAND.
  • Every open choice became a manifest setting, not a default argument. Four settings in rung 1 each move the rejection rate by 5–15 points. A number produced by a hard-coded opinion is not reproducible even by its author.
  • Splits are by document, not by mention — mentions from one post share its wording and its annotator — and stratified by drug family, because CADEC is 80% Lipitor and the human-agreement ceiling we cite was measured on the other one.
  • Missing rungs were reported, never faked. For the months the ladder was half-built, half a ladder honestly labelled was the result. The scorer is injected the same way, so accuracy columns were written empty rather than guessed.
  • The call cache is architecture, not convenience. Every model call is keyed and written to disk, so a re-run costs nothing, an interrupted run resumes, and results files become disposable derivatives rather than the only copy of an experiment.
  • A finding we published to ourselves and retracted: on a 10-item smoke run, cross-prompt vote dispersion looked like a better abstention signal than self-reported confidence. At n=60 it isn't. Nine errors was too small a base.
05Structure
Seven beats, practitioner voice.

Suggested article structure

The ladder is measured end to end now, so the piece leads with the curve and spends its middle on why each number can be trusted — the measurement discipline is the story.

  1. Every agent is 90% harness, built by vibes. The hook. Name the seven layers in a paragraph each and move on — they are not the contribution.
  2. The curve, once, on held-out data. One run, frozen config, three cost currencies never fused. One paid rung net negative, one never fired, the two that work refuse rather than answer. The figure the reader came for; everything after explains why it can be believed.
  3. You can measure a layer before you build the layer above it. Replay your deterministic gate over the answer key, where every rejection is false by construction. It caught three faults that would otherwise have shipped as a plausible 9.3% rejection rate — errors every paid rung above would have inherited.
  4. What a free layer actually buys. Exact on its own classes, blind on the interesting one, and 57% of even a perfect answer set left unverifiable. Reframe: free filter plus paid resolvers for the residue.
  5. The paid rungs, honestly. Never ask a model to recall an identifier (0.018 vs 0.171 for more tokens); a voting rung's number is a sample, and its first build destroyed verified answers on 1-0 “majorities”; the judge's separation partly lived in an accidental prompt duplication. Running thread: for small models, presentation IS measurement.
  6. Abstention and the person. The bill is a count, not a currency conversion; the queue holds 45 answers that were already right; the oracle ceiling proves the residual gap is span boundaries — which names the next rung to build, the real use of a ceiling.
  7. Decision rules. Measure the permissive setting's false-vouch rate before shipping it. Pin the vocabulary release. Don't let a validation layer filter the input to the layers you are measuring. Check whether your reference list came from your answer key. Hold presentation fixed or you are measuring two things. Cite the run id on any sampled rung. Spend your test split once.

07Limits

Limitations to state plainly

Everything in band 03 is dev-side and unvalidatable. The test split was spent on 2026-08-26 and this repo has no held-out data left. The audit's numbers come from 40 dev documents and from read-only replays of two archived runs; where a test-split artifact is used it is a labelled counterfactual, and the reported test numbers in band 02 are unchanged by any of it.

Two of the audit's cleanest results rest on small counts. Rung 3's fix/break tally is 18 and 21 scorable changes; the record that shipped on a stale warrant is one record. They are existence proofs of a mechanism, not rates — and the mechanism is the claim.

A single-draw confidence interval that excludes zero is not a result. Three independent draws killed the one rung 0 arm that a single draw plus a paired bootstrap had called significant: +0.0217 with a CI of [+0.0000, +0.0433], then +0.0087, then −0.0089. The paired bootstrap resamples the documents of one draw, so it prices the corpus sample and nothing else. Three draws plus the bootstrap, never one alone — and never ten-document subsets, which overstate both effect size and variance.

Exact F1 above ~0.70 is unreachable here for any system, including a perfect one. The answer key's own span-boundary convention is only ~67% deterministic: over 25,002 boundary decisions, 66.9% fall at tokens gold treats one way ≥95% of the time, 20% lean, and 13% are genuinely mixed — “terrible” is kept inside a span 52% of the time, “very” 70%, “in” 40%. A perfect learner of that convention gets ~0.92 per boundary and a span needs two, capping the exact-span rate near 0.85; composed with the measured detection and retrieval ceilings that gives F1 ~0.68 with every component at its best. Every 0.70-class claim here is therefore stated on overlap, with exact reported beside it as the stricter, capped number.

  • The test split was spent exactly once, so its CIs are the claim. 60 documents, 290 scorable mentions: F1 0.204 lives in [0.150–0.260]. Nothing was tuned on test and nothing re-run — which also means no second draw exists to average with. Report the interval, not the point.
  • Test above dev is partly split luck. Shipped F1 0.131 (dev) vs 0.204 (test), CIs barely overlapping, no test tuning anywhere in the pipeline. Generalisation is the honest first-order read; the second-order read is that the 40-document dev set was the harder draw. Say both.
  • Rung 3's numbers are samples. Temperature resamples differ run to run — dev gained +5 net correct, the one test draw gained zero — so every voting number carries its run id, and the rung's value claim is bounded by a between-draw spread that two draws cannot estimate.
  • The judge is 2B judging 20B — the wrong way round, kept as the measured lesser evil after the domain-adapted 7B alternative failed to return parseable verdicts at all. Every rung 4 number carries this.
  • The oracle desk is a dev-only ceiling. Derived from gold, labeled on every row, refused on the test split by construction. No real human desk session exists; human minutes appear only “at the declared rate”.
  • The MedDRA check cannot be trusted as configured. Its reference table is derived from the answer key. It is reported, not scored, and any number from it carries the caveat.
  • Contamination. CADEC is public and from 2015, so it is almost certainly in pretraining. It inflates rung 0, which makes the ladder's gains look smaller — the conclusion is conservative. The v2 slice is the check, and is not run yet.
  • Human ceiling. Strict span agreement between CADEC's own annotators was about 68.7 on the diclofenac posts. A system near 0.69 strict span F1 is at the noise floor of the answer key, not underperforming.
  • The abstention target is thin on the test split: 3 CONCEPT_LESS mentions in 290 scorable. Abstention accuracy against concept-less gold cannot be separated from noise there.
  • The confidence gate never earned a threshold. The 2B judge's confidence is nearly two-valued (a τ=0.95 shelf keeps 5.4% coverage — too thin to gate on), so rung 5 gates on verdicts, not confidence. A calibrated distribution remains unbuilt.
  • Near-miss corruption is synthetic. The pool is built from concepts sharing a head word — a proxy for the confusions a normalisation model makes, not a sample of them. The 19% is a property of the check under a plausible error model, and should be quoted that way.
